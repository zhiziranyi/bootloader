# FlashSafe Pro 本地上位机设计

## 目标

复用 `html/` 的现有工作台，提供一个仅监听 `127.0.0.1` 的本地上位机，在浏览器里完成串口 CLI、固件发布、启动 OTA 文件服务器、下发 OTA 命令和触发 PlatformIO 串口烧录。

## 架构

`tools/webui.py` 是唯一的本机特权边界：它托管 `html/index.html` 及静态资源，并以 JSON API 管理串口、受控子进程和项目内固件文件。HTML 只调用本机 API，不直接访问文件系统或执行命令。串口由后端单实例占用；读取线程把日志放入有限环形缓冲区，前端轮询显示。

## 操作范围

- 串口：枚举、打开/关闭、读取日志、发送 CLI 命令和一键拼装 `upgrade net <url>`。
- 发布：运行现有 `release_firmware.py`，生成双槽签名包和发布清单。
- OTA 服务：启动/停止现有 `fw_server.py`，默认服务 `firmware/`。
- 串口烧录：仅可选择 `bootloader`、`app_a`、`app_b` 三个固定 PlatformIO 环境；上传端口必须是 `COM` 加数字。
- 继续保留密钥轮换、下载固件包、发布清单和公钥功能。

## 安全和故障处理

所有接口只接受 JSON 且校验端口、版本、目标和端口号；子进程用参数数组启动，绝不拼接 shell 字符串。私钥下载仍要求显式确认。若串口被友善串口助手占用、PySerial 不可用或 PlatformIO 子进程正在运行，页面显示后端错误而不破坏设备状态。页面明确提示：进入 Bootloader CLI 仍需在硬件复位后的三秒窗口点击“发送任意字符”，ROM 串口烧录仍需用户按 BOOT0/复位接线规则操作。

## 验收

无硬件测试覆盖输入验证、允许的上传目标和 HTML 所需控件；完整工具测试通过。手工验收为：启动 `python tools/webui.py` 后，访问本机页面可看到串口与服务器状态，能连接 COM3、发送 `status`/OTA 命令并实时接收日志。
